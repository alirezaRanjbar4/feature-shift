# Design and limits

Each file is read once as a bounded byte snapshot, SHA-256 hashed, decoded as strict UTF-8 and parsed one complete JSON object per physical line. Properties are checked recursively for duplicates. Each dataset has exact unique IDs; feature names are sorted ordinally and the entire feature set must match every row and the other dataset. Additional top-level metadata is ignored; nested duplicate properties still fail. Report paths and raw rows/IDs are not echoed.

For each feature the implementation uses incremental mean and population variance (`sum((x - mean)^2) / N`), a signed candidate-minus-reference mean difference, reference-standardized mean difference `(candidateMean - referenceMean) / referencePopulationStdDev`, and counts strictly below/above the reference min/max. Zero or numerically underflowed reference standard deviation produces a null standardized difference; it is never silently treated as zero. Nonfinite intermediate or final statistics fail rather than serialize invalid JSON. Because floating-point arithmetic is order-sensitive, results can differ at the last bits when row order changes.

Both inputs have a 32 MiB, 50,000-row, 1 Mi UTF-16-character per line, 32-feature, 256-character ID, 64-character name and depth-32 JSON limit. Values must be finite with absolute magnitude at most `1e12`. The full snapshots, parsed features and IDs are kept in memory; these workload bounds are not a security sandbox. Reads are not an atomic snapshot if inputs are modified concurrently.

The comparison describes marginal numeric features. It does not calculate PSI, KL/JS divergence, p-values, confidence intervals, significance, categorical statistics, conditional or joint distribution shifts. It does not establish cause, model quality, representative sampling, identity independence or a universal alert threshold. Reference-standardization is asymmetric and can be large for a small reference scale; zero-reference-variance is intentionally undefined. Overlapping IDs are a warning signal, not proof of leakage, and non-overlapping IDs do not prove independence. Review aggregate statistics, names and hashes for sensitivity.
